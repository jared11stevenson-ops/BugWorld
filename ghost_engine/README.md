# GHOST ENGINE

A headless game foundry: simulate a persistent RPG world, evolve one of its mechanics under measurable tests,
compile the validated result into a Godot 4 project, and keep the Godot build locked to the headless simulation.

Everything below was actually run in this repo. Numbers come from `evidence/` (generated by code, not typed by hand).
Read **Limitations** before trusting any of it.

## What exists

| System | Where | State |
|---|---|---|
| **World Kernel** | `ghost/kernel/` (Python), `godot/ghost/kernel.gd` (GDScript twin) | Deterministic integer-only sim: 6 towns, 3 factions, 24+ NPCs with 8 behaviour policies, potion economy with traders, gold ledger, combat, grudges/affinity, faction wars/peace, deaths with heirs, causally-linked event history |
| **Timelines** | `ghost/kernel/timeline.py`, `godot/ghost/timeline.gd` | Snapshots, deterministic rewind+replay, branching alternate realities, interventions (kill, give gold, force relations, change a rule) |
| **Possibility Engine** | `ghost/lab/evolve.py` | Population search over a parametric combat-mechanic family; seeded with 3 hand-written (Claude) design proposals which are evaluated like any other candidate |
| **Causal Laboratory** | `ghost/lab/causal.py` | Paired-seed A/B worlds, counterfactual branches with CIs, 150-ruleset exploit fuzzing, one-at-a-time sensitivity |
| **Evolution Engine** | `ghost/lab/evolve.py` | Elitism, module-level crossover (crit/guard/power/heal/fatigue), hall-of-fame archive, held-out validation, per-module ablation |
| **Experience Intelligence** | `ghost/lab/tournament.py` | Structural proxies (below). Explicitly *not* a measure of fun |
| **World Compiler** | `ghost/compiler/` | Validated ruleset -> `godot/generated/` (`rulesets.gd`, `golden.gd`, `action_bar.tscn` with rule-derived tooltips, `assets_required.json`, `manifest.json`). **Gate:** refuses to compile unless held-out evidence passes |
| **Living Twin** | `godot/tests/`, `ghost/twin.py` | Godot headless reproduces Python state digests bit-for-bit, incl. fuzzed rulesets |
| **Playable Godot game** | `godot/ghost/main.tscn` | World viewer: step/rewind/fork/switch timelines, god-mode interventions, NPC histories with consequence chains, interactive duel using compiled rules, 1–5 fun rating written to `user://human_feedback.jsonl` |

## Run it

```bash
cd ghost_engine
python3 -m unittest discover -s tests            # 21 tests (Godot tests need GODOT_BIN, Godot 4.5 headless)
python3 -m ghost.lab.experiments                 # ~4 min, writes evidence/lab/* and evidence/REPORT.md
python3 -m ghost.compiler.compile                # gate + generate godot/generated/*
GODOT_BIN=... python3 -m ghost.twin 24 400       # fuzz parity Python vs Godot
godot --path godot                               # play (4.4+; developed on 4.5)
```

## Headline experiment: evolving the combat mechanic

Combat is simultaneous-action (Attack / Guard / Power / Heal) with 11 integer parameters in 5 modules. The baseline
(`v0`) has an *intended* flaw: Power is strictly better than Attack. Tournament of 8 policies, equal-stat duels.
Candidates are chosen on **train** seeds; every number below is on 8 disjoint **held-out** seeds
(`evidence/REPORT.md`, `evidence/lab/holdout_validation.json`).

| | baseline v0 | Claude hand-proposals | evolved (3 independent runs) |
|---|---|---|---|
| fitness (0–1 proxy) | 0.529 | 0.556 – 0.626 | **0.946 – 0.968** |
| robust dominance (best worst-case matchup of any static strategy; ≤0.35 = every strategy has a counter) | 0.93 | 0.64 – 0.84 | **0.23 – 0.28** |
| rock-paper-scissors cycles among static strategies | 0 | 0 – 1 | **4.5 – 6.1** |
| actions the adaptive agents actually use (of 4) | 2 | 2 – 3 | **4** |
| improved on held-out seeds | — | 6–8 / 8 | **8 / 8** in all 3 runs |

The three runs converge on the same structure (Power that is interrupted by Attack, Guard that counters, modest
Heal with a vulnerability cost, mild fatigue). Ablation of the champion: power module +0.46, guard +0.35, heal +0.16,
fatigue +0.07, crit 0.00 — crit is a measured no-op.

**The metric was revised mid-project, openly.** The first evolution run (archived in `evidence/archive_metric_v1/`)
scored well, but ablation showed the champion had made Heal a trap (heals 5 HP, +70% damage taken) and Guard irrelevant:
only 2 of 4 actions were live. The optimizer had gamed my proxy. I added a *liveness* term (an action used by <5% of
adaptive agents' decisions is dead), re-ran everything, and added liveness to the compile gate. The same revision
applies to the baseline numbers; the earlier champion is not used anywhere.

### What the evolved rules did to the persistent world (not optimized for; measured)

30 paired worlds × 600 ticks, evolved − baseline (±95% CI): kills **−58 ± 9** (94.8→36.8), NPCs alive **+3.3 ± 0.8**,
faction wars **−0.9 ± 0.2**, wealth Gini −0.13 ± 0.05, gold-ledger error 0 in every world.
Whether a calmer world is *better* is a design judgment this system cannot make.

### Causal lab findings

Forking at tick 100 and comparing the next 300 ticks over 30 paired seeds: forcing a Crown–Guild war has a large,
detectable effect (+22.9 ± 4.2 kills); killing the deadliest or the richest NPC has **no detectable aggregate effect**
(CI spans 0) even though 100% of branches diverge. Divergence is not effect.

Exploit fuzz (150 random rulesets): 46 had a dominant strategy, 12 combat stalemates, 40 money inflation, 33 bankrupt
economies, 22 wealth runaways, 3 extinction risks, **0 ledger violations**. The ledger detector is validated by a test
that plants a free-gold bug and confirms it fires (`tests/test_lab.py`). Parameter associations in the report are
correlational.

## Living Twin verification

- `godot/tests/parity_test.gd`: 175 checks against golden traces from the Python kernel (RNG, payoff matrices, 72 duels,
  8 worlds × 4 digest checkpoints, event hashes, rewind/replay, branching) — **0 failures**.
- `ghost.twin`: 26 randomly fuzzed rulesets × 400 ticks replayed in Godot — **0 digest mismatches**.
- Negative controls: changing one divisor in the Godot aggression formula, or the fatigue floor 20→25, makes the
  parity test fail (checked on a scratch copy). The test can fail.
- Speed (this container, software only): Python ≈ 6.5k ticks/s, GDScript ≈ 2.4k ticks/s.
- `godot/tests/ui_smoke.gd` drives the real scene (step, rewind, fork, intervene, duel to the end, feedback record).
  Screenshots: `evidence/screens/`.

## Limitations (read these)

- **No human has played this.** Fun, "meaningful outcomes", and agency are only represented by structural proxies
  (dominance, counterplay, cycles, liveness, stalemates, skill expression). Their weights and the 6–16 round length band are my
  assumptions. The duel's rating hook exists but there is zero human data; do not treat fitness as enjoyment.
- The proxies were already gamed once (above); they can be gamed again. Fitness saturates: all three runs' train
  fitness ended at 0.968, so the search can no longer discriminate among good designs.
- "AI agents invent mechanics" is currently **parameter-level search plus 3 hand-written proposals**. There is no LLM in
  the loop and the mechanic family is fixed (I added `fatigue` by hand; evolution only tuned it). Open-ended invention
  is not implemented.
- Policies are a fixed set of 8 archetypes; "adaptive" agents are myopic best-responders. Held-out seeds do not test
  held-out *strategies*, so some overfitting to this policy set is possible.
- Only combat is evolved. Economy and world parameters are fuzzed/analyzed but not optimized.
- The GDScript kernel is a manual port. Parity is guarded by tests, not by construction; any kernel change needs
  `python -m ghost.compiler.compile` (regenerates goldens) and the Godot tests.
- The "playable game" is a text/control UI with built-in widgets. No art, audio, or content; `assets_required.json`
  lists what would be needed. Verified only on Linux headless / xvfb with Godot 4.5; not on Android or other platforms.
- No CI: tests run locally only.

## Next priorities

1. Collect real human ratings from the duel (and a second, differently-evolved ruleset for blind A/B) and test whether
   any proxy predicts them; recalibrate or drop proxies accordingly.
2. Make mechanic invention open-ended: a proposal interface (mechanic = small data program) so an LLM or human can add
   structural mechanics that the same pipeline evaluates, with anti-gaming checks like liveness generalised.
3. Co-evolve policies with rules (find strategies that exploit a ruleset) to attack the overfitting-to-policy-set risk.
4. Extend evolution to economy/world rules with multi-objective (Pareto) fitness instead of one weighted sum.
5. Generate the GDScript kernel from a single spec instead of hand-porting.
